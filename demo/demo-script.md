# Synthetic Reva presentation script

**Demonstration only: fictional patient, documents, visits, and dialogue.** Allow about six minutes. Start from the app's explicit Reset Demo action, then confirm Jordan Avery (Synthetic), nine records, two upcoming visits, and the completed September 8 visit. Static dates are anchored to September 12, 2026.

1. **Summary and preparation.** Open the September 17 Broken-leg follow-up. Read its concern, goal, and recovery questions. Generate the labeled local/demo brief. Expect the new fibula injury, August imaging, prior tibial procedure, and medication/allergy context. The resolved ear infection should be absent.
2. **Check the evidence.** Open the older right tibia procedure from a report source link. Show the implant inventory on page 2 and distinguish the 2019 nail from the new 2026 fibula fracture. Return to the visit and edit a question to describe walking comfort.
3. **Import and review.** Import `reva-synthetic-import-preparation-note.txt` from Files to add a distinct document. Inspect actual extracted text, edit its title or notes, save, and regenerate the visit brief to show updated source memory. For OCR, import `reva-synthetic-symptom-diary-scan.png` or its image-only PDF and inspect the actual extraction result. The unclear date needs review; keep `[unclear]` unless a presenter-supplied correction is explicitly labeled as such.
4. **Change the visit goal.** Open the September 15 Nausea and palpitation follow-up and generate its brief. Expect the symptom diary, labs, ECG note, medication/allergy context, and asthma note. It should differ from the orthopedic report, with the ear episode and leg imaging absent by default. Show the diary uncertainty and the exact TSH value in its original source. Optionally pin the ear record, regenerate, and show that explicit inclusion works; then unpin it.
5. **Simulate booking.** Use the app's booking flow, review the fictional clinic and permitted date/time constraints, and select a clearly simulated outcome. Observe progress and confirmation or the needs-user path. Reopen the visit list and confirm one appointment is created for one confirmed attempt. No real phone call occurs.
6. **Open a sample visit memory.** Open the completed September 8 visit and use the explicit sample-transcript action. Confirm the title says synthetic sample and no audio. Inspect speaker labels, relative timestamps, the discussion, preparation items, and unresolved questions. The sample states no diagnosis or medication change. A new microphone capture must remain a separate real local audio item with transcription unconfigured.
7. **Share and persist.** Export a prepared visit brief using the native PDF share sheet and inspect its source list. Reopen the app to confirm the imported note, edited question, and saved demo state persist. Use Reset Demo when the presentation is finished to restore the known starting set.

If camera scanning is unavailable in the simulator, use the bundled/importable image or image-only PDF. If microphone input is unavailable, use the clearly labeled text-only sample without claiming that audio was captured. If native OCR cannot read a source, retain its original and show the review/error state; the text note and text-layer PDFs provide a reliable intake fallback. The presentation can run without network access.

The intended functional local behaviors are source import/extraction where supported, source viewing, edits, deterministic report preparation, local persistence, and PDF export. Booking and authored summaries/dialogue are explicitly synthetic. Live AI summarization, live transcription, outgoing calls, and live Tiger access require separate configuration and are not demonstrated by this dataset.
