# Live recording captions

The browser recorder shows a muted live transcript beneath its recording controls, including in the `/mobile` web preview. This does not add streaming to the installed native SwiftUI recorder.

Start recording remains behind the doctor/everyone-present consent step. Audio from that same microphone stream is converted to mono PCM16 in an AudioWorklet and streamed to ElevenLabs Scribe v2 Realtime. The encoder uses the AudioContext's actual supported sample rate. Startup frames drain in order as the socket has capacity; the final partial frame is flushed before committing. Pausing, hiding the page, stopping, discarding, or leaving the workspace releases live capture; resume opens a fresh session. Navigating within the workspace preserves recording and captions. Caption cleanup never stops the original recorder's tracks.

The authenticated `POST /v1/audio/realtime-token` endpoint returns a temporary, single-use credential. Both the Vercel API and Swift server support it. Set `ELEVENLABS_API_KEY` on the server; the Swift server additionally requires private provider access. No new secret belongs in Vite or browser storage. Production CSP allows the fixed `wss://api.elevenlabs.io` destination. Unconfigured providers, dropped connections, or unsupported audio capture leave the original recording available and show a quiet unavailable message.

Live captions are an ephemeral preview. **Save recording always queues the complete original audio for standard transcription, then AI analysis and a sourced memory record.** No separate transcription, analysis, or memory confirmation is required. The recording page closes after durable saving; progress remains in the workspace. Review and transcript corrections remain available afterward. This uses **both** realtime and saved-audio transcription, with separate summary usage. Provider costs are listed on the [ElevenLabs API pricing page](https://elevenlabs.io/pricing/api).

Short clips, empty previews, unfinished partial text, a late live handshake, and failed live connections all follow that same saved-audio path. Live text never marks final transcription complete or becomes source evidence. Scribe starts live processing after roughly two seconds of audio, so shorter clips can legitimately have no live captions; see [commit behavior](https://elevenlabs.io/docs/eleven-api/guides/how-to/speech-to-text/realtime/transcripts-and-commit-strategies). Standard transcription still requires usable speech and an available configured provider. Silence and provider failures preserve the original audio and show an accurate processing state instead of invented text. Recovery is available after failure; normal waiting and AI backoff do not ask the user to initiate processing again.

The native app also queues final transcription, summary, and sourced memory when audio is saved, then closes the recording screen. Its queue belongs to the workspace, not the recording view, and progress appears with saved recordings. Pending stages survive app closure and resume when the workspace becomes active again. Original audio, completed transcripts, separate notes, and recoverable failures remain saved. Native recording still has no live-caption stream.

Notes keep their allotted space. A light edge fade and small directional chevron appear only when content extends above or below the viewport; the editor retains native keyboard scrolling and a thin scrollbar.

Validation uses synthetic audio and mocked provider/token responses: PCM encoding, startup buffering/backpressure, sample-rate agreement, interim/final events, partial-frame flushing, consented recorder lifecycle, pause/resume, late responses after discard, bounded network failures, authenticated routes, and notes overflow. Save-to-processing integration tests use the real store and queue for sub-second, missing/partial live text, unavailable realtime, and uploaded audio, with no confirmation calls or additional AI opt-in. Browser verification on September 12, 2026 exercised the actual AudioWorklet and MediaRecorder with a silent-output oscillator for 0.42-second captures, both immediate and post-stop handshakes; PCM, final commits, cleanup, and nonempty originals passed. Provider responses were synthetic. No microphone was opened and no provider audio was sent. A real provider stream remains unverified because the local server has no provider keys configured.

Provider contracts: [client-side streaming](https://elevenlabs.io/docs/eleven-api/guides/how-to/speech-to-text/realtime/client-side-streaming), [WebSocket reference](https://elevenlabs.io/docs/api-reference/speech-to-text/v-1-speech-to-text-realtime), [single-use tokens](https://elevenlabs.io/docs/api-reference/tokens/create).
